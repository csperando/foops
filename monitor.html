Multi-Monitor Detection Playground

A site can tell you have a second display without ever asking for permission. This page reproduces several of the techniques and reacts live as you plug in, unplug, or drag windows between monitors.

Based on the strongest signal available in this browser.

1. Window Management API — screen.isExtended

checking

A boolean flag exposed directly on window.screen, no permission prompt required. It was added specifically because sites were already inferring this via hackier means — this is almost certainly what the site you saw was using.

        not requested

        screen's label is also checked against the same virtualization hints as
        method 8 (e.g. this VM reports "VBOX monitor").

3. Permissions API state (no prompt)

        checking
        

        

        navigator.permissions.query() can silently check whether the
        window-management permission is granted/denied/prompt — without ever
        showing the user a dialog. A prior grant lets a site skip straight to method 2.
        

        

    


    
    

        

        
4. Heuristic: screen.availLeft / availTop

        checking
        

        

        Non-standard but long-supported properties. If a monitor is positioned to the left of
        or above the primary display, these go non-zero — a strong hint of a multi-monitor
        layout with zero permissions involved.
        

        

    


    
    

        

        
5. Heuristic: window position vs. screen bounds

        watching
        

        

        Polls window.screenX/screenY against screen.width/height.
        If the window is ever positioned (or dragged) outside the primary screen's bounds,
        there must be another display out there.
        

        
Try dragging this browser window onto your second monitor to trigger it.

        

    


    
    

        

        
6. Is isExtended being blocked or spoofed?

        checking
        

        

        A user (or a privacy browser/extension) can override screen.isExtended
        to always report false without removing it, which defeats simple
        feature-detection. This checks whether the getter is still native code, and cross-checks
        its answer against the independent heuristics above for consistency.
        

        

    


    
    

        

        
7. Hardware signal: display refresh-rate (vsync) timing

        measuring
        

        

        Counts requestAnimationFrame callbacks over a fixed window to measure the
        monitor's actual refresh rate from real vsync timing — not an OS-reported flag, so
        it's much harder to fake convincingly. Re-measures periodically; a shift in Hz with no
        display-settings change usually means the window crossed onto a different physical screen.
        

        
Drag the window to a monitor with a different refresh rate to see it change.

        

    


    
    

        

        
8. Context signal: is this even physical hardware?

        checking
        

        

        Reads the WebGL renderer string, which often names the virtual GPU driver in a VM
        (e.g. VMware SVGA3D, VirtualBox, Hyper-V, or a software renderer like llvmpipe/SwiftShader).
        This doesn't detect monitors directly — it's a trust modifier for the other seven
        cards. Inside a VM, "hardware" refresh-rate timing (method 7) is usually a synthetic,
        hypervisor-emulated 60Hz rather than a real vsync signal, and virtual display counts are
        whatever the hypervisor is configured to present.
